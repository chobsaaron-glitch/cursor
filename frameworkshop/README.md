# FrameWorkshop ERP

CRM + калькулятор оформления + склад + производство + касса для багетной
мастерской. Деньги в копейках, размеры в миллиметрах, интерфейс на русском.

Это самостоятельная система, а не копия FrameReady: та же предметная область
(заказ → изделие → компоненты → склад → производство → оплата), другой стек и
другой интерфейс.

Документы:

- [Архитектура](docs/architecture.md)
- [ADR](docs/adr.md)
- [ERD](docs/erd.md)

## Что уже работает

- Заказ клиента с несколькими изделиями, конструктор (паспарту до 7 слоёв,
  два багета, остекление, основа, фурнитура, услуги).
- Движок геометрии и движок цен (метр / chop / join / матрица / формула,
  пол `minMarkup`).
- Подтверждение резервирует материалы и создаёт техкарту; нехватка не
  откатывает заказ, а предлагает закупку.
- Канбан производства, таймер операций, обязательный чеклист ОТК.
- Частичные оплаты, не удаляемые платежи, независимые статусы
  (коммерческий / производство / оплата).
- Склад с резервом и отходом, закупки из дефицита, ABC и фин. отчёты.
- RBAC: администратор, приёмщик, мастер, бухгалтер, менеджер.
- Демо-база «Рама и свет»: 100+ багетов, клиенты, живые заказы.

## Стек

TypeScript, Next.js 15, React 19, PostgreSQL, Prisma 7, Tailwind CSS 4, Zod,
Vitest.

## Запуск

Нужны Node 20+ и PostgreSQL 16.

```bash
cd frameworkshop
cp .env.example .env
# поправьте DATABASE_URL и AUTH_SECRET
npm install
npx prisma migrate deploy
npm run seed
npm run dev
```

Откройте http://localhost:3000

| Роль | Вход | Пароль |
| --- | --- | --- |
| Администратор | `admin@ramaisvet.ru` | `demo12345` |
| Приёмщик | `priem@ramaisvet.ru` | `demo12345` |
| Мастер | `master@ramaisvet.ru` | `demo12345` |
| Бухгалтер | `buh@ramaisvet.ru` | `demo12345` |
| Менеджер | `manager@ramaisvet.ru` | `demo12345` |

Интеграционные тесты идут в отдельную базу (`TEST_DATABASE_URL`), чтобы
`vitest` не затирал демо-данные.

```bash
npm run typecheck
npm run test:unit
npm run test:integration
npm run build
```

## Принципы, которые нельзя нарушать

1. Расчёт геометрии и расчёт цены — разные модули.
2. Оплата не меняет коммерческий и производственный статус.
3. Финансовые строки не удаляются — только void / cancel / reverse.
4. Складское движение всегда пишет проводку в том же транзакционном блоке,
   что и изменение остатка.
5. В UI нет зашитых цен и фиктивных кнопок «Рассчитать».
